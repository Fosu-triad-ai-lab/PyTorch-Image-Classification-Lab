## 实验文件夹的标准结构（建好后）

按 `docs/项目规范.md`，4 个实验各自一个文件夹：

| 文件夹 | 实验 | 学时 | 分组 |
| --- | --- | --- | --- |
| `exp1_image_classification/` | 基于 PyTorch 的图像分类 | 8 | 1 人 |
| `exp2_text_sentiment/` | 基于 PyTorch 的文本情感分类 | 6 | 1 人 |
| `exp3_image_text_retrieval/` | 图像与文本多模态检索 | 6 | 1 人 |
| `exp4_modeling/` | 面向数学建模竞赛的 AI 建模与求解 | 12 | 3 人 |

每个实验文件夹内部统一为：

```text
expX_xxx/
├─ README.md      这个实验做了什么、怎么跑、结果怎么样
├─ train.py       训练入口
├─ evaluate.py    测试和画图（简单的实验可以并进 train.py）
├─ figures/       曲线、混淆矩阵等图
├─ logs/          训练日志
└─ checkpoints/   模型权重（不进 Git）
```

实验报告放在 `docs/` 下，命名成 `实验1报告.docx` 这种。

## 维护规则：动文件夹就更新结构

1. 新增、删除、重命名文件夹，或者增删关键文件，**在同一个 commit 里更新上面的「当前项目结构」**。
2. 当前结构只写实际存在的东西；还没建的实验文件夹放到「标准结构」一节，不要混进当前结构。
3. 每个实验的 `README.md` 至少写清楚：数据集、怎么跑、主要超参数、最好结果、跑了多久。
4. AI 助手改目录结构时也必须遵守这条；不确定放哪先问 Lucky。

提交前检查：

- [ ] `git status` 里有没有新目录或新文件？README 结构是否同步？
- [ ] 有没有把 `data/`、`checkpoints/`、密钥或密码提交上去？
- [ ] 实验 README 的结果和 `logs/`、`figures/` 对得上吗？

## 给只用网页版 AI 的同学

网页版 DeepSeek 看不到这个仓库，它只能读你贴给它的文字。按下面顺序用，别一上来就让它猜文件内容：

1. 先把「当前项目结构」整段复制给它。
2. 再说你的任务，例如“帮我写实验1的 train.py”。
3. 让它先告诉你还需要读哪几个文件，你再逐个把文件内容贴过去。
4. 做实验通常要贴 `docs/项目规范.md` + 对应实验的 `README.md`；问节点贴 `docs/节点使用说明.md`；问 AI 规则贴 `AGENTS.md`。

可以直接复制的模板：

```text
你是我的编程助手。下面是我的项目结构：

[粘贴「当前项目结构」]

我的任务是：[写清楚要做什么]

请先告诉我需要读哪些文件，我再把内容贴给你。
不要猜文件内容；不确定的地方直接问我。
```

注意：AI 可以帮你写，但代码要自己跑通、自己讲得清楚；报告里的数字必须和日志、图表对得上。

## 怎么跑

实验1 的运行命令见 `exp1_image_classification/README.md`。其余实验的运行命令写在各实验的 `README.md` 里，不要在这里重复。

- 实验统一在 DGX 云节点上跑：想登节点先找 LXJ，连接和环境激活见 `docs/节点使用说明.md`。
- 代码同步优先 git：节点上克隆了同一仓库（`~/cnn/lucky/lab`），直接 pull/push；权重、数据集等不进 Git 的文件用 scp/rsync 传，见节点说明第 5 节。
- 云节点规则以 `docs/Spark云节点访问与使用手册(华硕).md` 第八节为准。

## Git 约定

- **Lucky（管理员）**：直接在 `main` 上 commit、push；AI 助手可以随手 commit，别动分支。
- **其他两人（写权限）**：`main` 受分支保护，不能直接 push——改动走自己的分支 + PR：开分支 → commit → push 分支 → 网页上点 **Compare & pull request** → 群里喊 Lucky 合并。详细步骤见 `docs/项目规范.md` 第六节。
- 共同约定：每天开工先 `git pull`；一次提交只做一件事，信息写中文短句（如 `实验1：完成数据加载`）；只改自己负责的文件夹；遇到冲突不要 `--force`，停下来问。
