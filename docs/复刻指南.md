# 复刻指南：把实验1～3 在自己名下重跑一遍

> 给另外两位同学。实验1～3 每人独立完成、独立交报告：仓库里的代码可以直接用（在报告里写明参考出处），但**训练必须自己跑**，日志、图表、报告都必须是自己生成的。本文是完整流程，各步骤细节见对应文档。

## 一、准备账号

- 节点账号：找 LXJ 开通，连接方法见 `节点使用说明.md`。
- GitHub 写权限：找 Lucky 加进 `Fosu-triad-ai-lab` 组织（有写权限后走"自己的分支 + PR"，见 `项目规范.md` 第六节）。

## 二、把仓库拿下来

自己电脑（改代码、写报告都在这里，改动走分支 + PR）：

```bash
git clone git@github.com:Fosu-triad-ai-lab/PyTorch-Image-Classification-Lab.git
cd PyTorch-Image-Classification-Lab
git switch -c exp1-<你的名字>      # 分支名带用途和名字，如 exp1-arcanicy
```

节点（只跑训练，HTTPS 地址只拉不推）：

```bash
mkdir -p ~/cnn/<你的名字>
git clone https://github.com/Fosu-triad-ai-lab/PyTorch-Image-Classification-Lab.git ~/cnn/<你的名字>/lab
```

## 三、环境

- 节点：`source ~/venvs/cnn/bin/activate`。共享环境里 torch / torchvision / transformers / matplotlib 都有，缺包在群里找 Lucky，**不要自己 pip install**（几个人同时装会冲突）。
- 自己电脑：Python 3.12 + torch（版本见各实验 README）。三个实验都不大，PC 级显卡也能跑，只是慢一些。

## 四、准备数据（.gitignore 排除的部分）

| 实验 | 内容 | 大小 | 怎么准备 |
| --- | --- | --- | --- |
| 实验1 | CIFAR-10 | 178MB | **不用准备**：`train.py` 里 `download=True` 自动下载。节点下载慢时可从 lucky 复制 `exp1_image_classification/data` |
| 实验2 | aclImdb 解压后 + glove.6B.100d | 490MB + 332MB | 从 lucky 复制：`cp -r ~/cnn/lucky/lab/exp2_text_sentiment/data ~/cnn/<你的名字>/lab/exp2_text_sentiment/`；或按 exp2 README 用 hf-mirror 重新下载 |
| 实验3 | Flickr8k 图片 + 文本标注 + bert-tiny 模型 | 1.1GB + 10MB + 18MB | 从 lucky 复制 `~/cnn/lucky/lab/exp3_image_text_retrieval/data` 下的 `Flicker8k_Dataset/`、`Flickr8k_text/`、`models/bert-tiny/`；或按 exp3 README 下载（GitHub release 节点直连不通） |

两条**不要复制**的：

- `exp3/data/features/`：跑一次 `python precompute_features.py`（约 8 秒）自动生成，复制了也是旧缓存。
- `checkpoints/`：**不要复制别人的权重**。复刻就是自己重新训练，权重、logs、figures 都由训练自动生成；拷别人的权重等于跳过了实验本身。

以上复制都在节点内部 `cp -r` 完成，不走 scp、不占公网。

## 五、跑实验（节点上放 tmux）

先 `nvidia-smi`、`tmux ls` 看有没有人在跑；一人一个目录、一个会话，名字用自己的。命令都在各实验目录下执行：

| 实验 | 命令 | 时长参考（GB10） |
| --- | --- | --- |
| 实验1 | `python train.py`、`python train.py --use-bn`、`--use-dropout`、`--use-bn --use-dropout` 四组；再分别 `python evaluate.py --checkpoint checkpoints/<实验名>.pth` | 四组训练 + 评估约 9 分钟 |
| 实验2 | `python train.py --embedding-init random` 和 `glove` 两组；两组 `evaluate.py`；`noise_test.py --checkpoints checkpoints/lstm_random.pth checkpoints/lstm_glove.pth` | 全部约 4 分钟 |
| 实验3 | `python precompute_features.py` 一次；8 组训练 + 评估命令见 exp3 README「怎么跑」；最佳组补一次 `python rank_stats.py --checkpoint checkpoints/infonce-d512-ep30.pth` | 全部约 3 分钟 |

完整命令、参数含义以各实验 `README.md` 为准。

## 六、结果回仓库、写报告

1. 节点上不能 push：把 `logs/`、`figures/` 用 scp 拉回自己电脑（命令见 `节点使用说明.md` 第 5 节）；直接在自己电脑跑的忽略这步。
2. 在自己电脑的仓库里 commit 到自己的分支，push 后网页上开 PR，群里喊 Lucky 合并。
3. 报告结构可参考 `docs/实验1报告.md` ～ `实验3报告.md`，但**数字必须来自自己的 logs 和 figures**；参考了仓库代码要在报告里写明出处（`项目规范.md` 第七节）。
4. 按课程要求把 md 转成 docx 交；放进 `docs/` 前先在群里约定命名（如加名字后缀或按人建子目录），避免三人同名互相覆盖。

## 七、两条红线（评分相关）

- 固定种子 42、同一台节点，重跑出来的数字和 Lucky 的一致是**正常且应该的**，这叫复现；但把别人的 `logs/`、`figures/` 直接拷走交报告属于数据造假/抄袭，按大纲扣该报告得分的 50%～100%。
- 每天开工先 `git pull`；不碰别人的目录、进程和 tmux 会话；密码不写进仓库、文档、截图。节点使用红线以 `节点使用说明.md` 第 10 节为准。
