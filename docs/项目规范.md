# 项目规范

这是《AI 项目实训》的仓库约定。目标很简单：代码自己能跑、别人看得懂，实验结果有记录，写报告时材料齐全。不搞复杂流程。

## 一、目录结构

一个实验一个文件夹，名字用英文小写加下划线：

```text
PyTorch-Image-Classification-Lab/
├─ docs/                        课程资料、实验报告
├─ exp1_image_classification/   实验1 图像分类
├─ exp2_text_sentiment/         实验2 文本情感分类
├─ exp3_image_text_retrieval/   实验3 图文多模态检索
├─ exp4_modeling/               实验4 数学建模（3 人组）
└─ .gitignore
```

每个实验文件夹内部保持同样的结构：

```text
expX_xxx/
├─ README.md      这个实验做了什么、怎么跑、结果怎么样
├─ train.py       训练入口
├─ evaluate.py    测试和画图（简单的实验可以并进 train.py）
├─ figures/       曲线、混淆矩阵等图
├─ logs/          训练日志
└─ checkpoints/   模型权重（不进 Git）
```

实验报告放在 `docs/` 下，命名成 `实验1报告.docx` 这种，一看就知道是哪个。

## 二、命名

- 文件和变量：英文小写，单词间用下划线，如 `train_loader`、`best_acc`。
- 类名：大驼峰，如 `SimpleCNN`。
- 常量：全大写，如 `BATCH_SIZE`。
- 注释、文档、提交信息：中文。
- 别用拼音缩写，也别用 `a`、`tmp`、`test2` 这种名字。

## 三、每个实验都要有的东西

1. 固定随机种子（统一用 42），保证重跑结果差不多。
2. README 里放一张小表，记录：数据集、主要超参数、训练轮数、最好结果、跑了多久。
3. 图：训练/验证的 loss 和 accuracy 曲线；分类实验加混淆矩阵。
4. 错例分析：挑几张分错的样本，写清楚可能的原因。
5. 训练日志留在 `logs/`。小的文本日志可以提交，方便查过程。

## 四、代码习惯

- 用 `argparse` 传超参数，不要每次去代码里改数字。
- 路径不要写死成 `E:\...`，用相对路径或脚本所在目录。
- 数据处理、模型定义、训练循环分开写，别全塞进一个 200 行的函数。
- 保存验证集上最好的模型，不是最后一个 epoch 的模型。
- 每个 epoch 打印：第几轮、训练 loss、验证 loss、验证准确率。
- 简单清晰的代码比“高级”的代码好。看不懂的技巧不要用。

## 五、数据和模型文件

- 数据集放 `data/` 或 `datasets/`，不提交；下载地址和整理方法写进 README。
- 模型权重（`*.pth`、`*.pt`、`*.ckpt` 等）不提交。
- 大于 50MB 的文件，提交前先想一下是不是必须。
- 虚拟环境、缓存文件也不提交。

## 六、Git 怎么用（最简版）

仓库在 GitHub：`Fosu-triad-ai-lab/PyTorch-Image-Classification-Lab`。按角色分两种提交方式：

- **Lucky（管理员）**：直接在 `main` 上 commit、push；AI 助手也可以随手 commit，不动分支就行。分支保护不限制管理员，所以这条路是通的。
- **其他同学（有写权限）**：`main` 开了分支保护，不能直接 push，改动统一走"自己的分支 + PR"。完整一轮：

  1. 在自己电脑上克隆主仓库（只有这一个网址，不用 Fork）：
     `git clone https://github.com/Fosu-triad-ai-lab/PyTorch-Image-Classification-Lab.git`
  2. 开一个自己的分支，名字带用途：`git switch -c exp2-arcanicy`
  3. 改完提交、推自己的分支：`git add .` → `git commit -m "实验2：完成数据加载"` → `git push -u origin exp2-arcanicy`
  4. 打开仓库网页，顶部点黄条 **Compare & pull request**，标题写中文短句，点 **Create pull request**
  5. 群里喊 Lucky review 合并；合并后 `git switch main` → `git pull`，再用 `git branch -d exp2-arcanicy` 删掉分支

  第一次 push 会弹浏览器让你登录 GitHub，登录一次就够了；直接 `git push origin main` 会被分支保护拒绝，报错会引导你走 PR，照着做就行。

刚开始学也不用怕，先记住这 4 条：

1. 每天开工先 `git pull`；收工前 push 好自己的分支（Lucky 直接 push `main`）。
2. 只改自己负责的文件夹；要动别人的文件，先在群里说一声。
3. 一次提交只做一件事，信息写中文短句，比如 `实验1：完成数据加载`；提交前先 `git status` 看一眼。
4. 遇到冲突或报错，不要 `git push --force`，也不要删别人的分支或提交；停下来问，不要自己硬修。

Lucky 的机器和 DGX 节点是同一个仓库（节点上在 `~/cnn/lucky/lab`），哪台机器改完都直接 push，换机器前先 `git pull`，代码不靠 scp 传。节点上只跑训练：用 HTTPS 地址 clone/pull 公开仓库不需要登录任何 GitHub 账号，只拉不推。

实验 1 到 3 各做各的文件夹。实验 4 是三个人一起改：小步提交、PR 里说清楚改了哪部分，就不容易冲突。

## 七、实验报告和诚信

- 大纲规定：报告抄袭、数据造假、缺少关键步骤记录，直接扣该报告得分的 50%–100%。
- 参考了别人的代码、文章，要写明出处；图和数字必须是自己跑出来的。
- AI 工具可以辅助，但内容要自己看懂、能讲清楚，代码要自己能跑通。
- 报告里的数字要和日志、图表对得上。

## 八、运行环境和做法

- 实验统一在 DGX 云节点上跑：NVIDIA GB10、121GB 统一内存；训练环境 `source ~/venvs/cnn/bin/activate`（Python 3.12、torch 2.14.1+cu130）。
- 想登节点先找 LXJ；登录、环境激活、tmux 见 `docs/节点使用说明.md`，红线以官方手册第八节为准。
- 代码同步优先 git：节点上的仓库在 `~/cnn/lucky/lab`，直接 pull/push；权重、数据集等不进 Git 的文件用 scp/rsync。
- 实验1 用 CIFAR-10 就够，不要下完整 ImageNet（太大，没必要）。
- 实验2 用 IMDB，词表先控制在 1 万到 2 万。
- 实验3 用小型图文配对数据，图像模型选 torchvision 自带的小模型（如 resnet18）。
- 实验4 是三人组，建模、编程、写作的分工写进 `exp4_modeling/README.md`。
- 先用小数据子集或 1～2 个 epoch 把流程跑通，再换全量；batch size 从 32 或 64 起步。
