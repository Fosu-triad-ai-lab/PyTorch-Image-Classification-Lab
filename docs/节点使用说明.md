## 0. 这台机器是什么

一台放在机房的 Linux 电脑，用 SSH 从自己电脑连上去。代码、数据、训练都在那台机器上，你的电脑只是遥控器。

配置：NVIDIA GB10，121GB 统一内存，Ubuntu 24.04（ARM64），Python 3.12。

三个习惯：

- 只写自己的目录 `~/cnn/你的名字`。
- 长任务放 tmux，断网也不停。
- 结果及时拉回本地，节点赛后清空。

## 2. 第一次登录（Windows）

1. 按键盘上的 Win 键，输入 `PowerShell`，回车打开。
2. 复制下面这一行，粘贴进去，回车：

```bash
ssh -p 6022 asus_gx10@61.172.235.130
```

3. 第一次会问 `Are you sure you want to continue connecting?`，输入 `yes`，回车。
4. 然后输入密码。屏幕上不会显示任何字符，这是正常的；输完直接回车。
5. 看到类似 `asus_gx10@gx10-7390:~$` 的提示符，就是成功了。

连不上时看这里：

- `Permission denied`：密码或用户名错了。
- `Connection timed out`：网络或节点问题；等 20 到 40 秒再试，不要连续狂刷。
- `ssh 不是内部或外部命令`：Windows 没装 OpenSSH 客户端。设置 → 应用 → 可选功能 → 添加功能 → 找“OpenSSH 客户端”装上。
- 还是不行：找秋爽，不要自己重启节点。

## 3. 登录后先做 3 个检查

每次都先跑这三行：

```bash
nvidia-smi
df -h
free -h
```

看什么：

- `nvidia-smi`：能看到 `NVIDIA GB10`，说明 GPU 正常；顺便看显存有没有被别人占着。
- `df -h`：看磁盘用了多少，至少留 20% 空闲。
- `free -h`：看内存，这台有 121GB，一般够用。

## 4. 激活训练环境

```bash
source ~/venvs/cnn/bin/activate
python -c "import torch; print(torch.__version__, torch.cuda.is_available(), torch.cuda.get_device_name(0))"
```

正常输出：

```text
2.14.1+cu130 True NVIDIA GB10
```

说明：

- 命令行前面出现 `(cnn)`，表示环境已激活。
- 如果报 `No module named torch` 或其他错：不要自己 `pip install`，在群里找 Lucky。环境只装一次，几个人同时装会冲突。
- 如果忘了激活，直接用系统 Python，会报 `externally-managed-environment`，回到本节第一行重新激活。

## 5. 传代码、收结果

这些命令在本地 PowerShell 里执行，不是在节点里。

先在节点上建自己的目录（SSH 登录后执行一次）：

```bash
mkdir -p ~/cnn/lucky
```

把 `lucky` 换成你自己的名字，比如 `arcanicy`、`axcud`。

本地 → 节点：

```bash
# 传单个文件
scp -P 6022 ./train.py asus_gx10@61.172.235.130:~/cnn/lucky/

# 传整个文件夹
scp -P 6022 -r ./exp1_image_classification asus_gx10@61.172.235.130:~/cnn/lucky/
```

节点 → 本地：

```bash
scp -P 6022 asus_gx10@61.172.235.130:~/cnn/lucky/results.json ./
scp -P 6022 asus_gx10@61.172.235.130:~/cnn/lucky/model.pt ./
```

注意：

- `scp` 的端口参数是大写 `-P`，`ssh` 是小写 `-p`，别搞反。
- CIFAR-10 不用传，代码里 `download=True` 让节点自己下。
- 100MB 到 1GB 用 `rsync` 断点续传；超过 1GB 禁止用 scp，在节点里下载。
- 节点不备份，训练完及时把结果拉回来。

## 6. 跑训练（必须放 tmux）

tmux 是一个“不会断的窗口”。SSH 断线，前台任务会停；tmux 里的任务会继续跑。

```bash
# 1. 新建一个会话，名字用自己的
tmux new -s cnn-lucky

# 2. 激活环境，进自己的目录
source ~/venvs/cnn/bin/activate
cd ~/cnn/lucky

# 3. 跑训练
python train.py --epochs 20 --batch-size 128
```

想先离开、让训练继续跑：

1. 按 `Ctrl+B`，松开。
2. 再按 `D`。
3. 回到普通命令行，任务还在后台跑。

回来后：

```bash
tmux ls                     # 看有哪些会话
tmux attach -t cnn-lucky    # 回到自己的会话
```

自己的会话不用了：

```bash
tmux kill-session -t cnn-lucky
```

只关自己的，不要关别人的。

## 8. 收工前 3 件事

1. 把结果拉回本地：模型 `model.pt`、日志、图表、`results.json`。
2. 自己的 tmux 会话不用了就关掉；还在跑就 detach。
3. 跑一下 `df -h`，删掉自己的旧 checkpoint、下载包，别把磁盘塞满。

节点不会备份，比赛结束会清空。代码记得 push 到仓库，结果记得拉回本地。

## 9. 三个人一起用（确认允许后再按这个来）

- 一人一个目录：`~/cnn/lucky`、`~/cnn/arcanicy`、`~/cnn/axcud`。
- tmux 会话用自己的名字：`cnn-lucky`。
- 跑大任务前在群里说一声；先 `nvidia-smi` 和 `tmux ls` 看看有没有人在跑。
- 不 kill 别人的进程，不删别人的文件。
- 只写 `~/cnn`、`~/venvs/cnn`、`~/bench/cnn`。
- 不要动 `~/.ollama`、`~/bench/models`、`~/bench/dl`。
- 如果有人在跑基准测试，测速数字会不准，等它跑完再测。

## 10. 红线（违反会被收回节点）

- 不转借账号：不发班级群、不给别队、不发到公开地方。队内共享先问秋爽。
- 不改登录密码、SSH 配置、防火墙、路由、用户权限、驱动、BIOS。
- 不 `sudo apt` 装 CUDA/驱动；不 reboot、不 shutdown。
- 不把 Jupyter、文件管理器、Web 终端裸奔到公网；要开就设 token/密码，或者走 SSH 隧道。
- 长任务用 tmux；单文件超过 1GB 不用 scp；磁盘留 20%。
- 密码不进仓库、文档、日志、截图、命令历史。
- 出问题找秋爽，不自己重启、重装。

## 11. 常见报错

| 现象 | 怎么办 |
| --- | --- |
| `Permission denied` | 密码或用户名错了 |
| `Connection timed out` | 等 20 到 40 秒重试，不要狂刷；还不行找秋爽 |
| `ssh 不是内部或外部命令` | 装 Windows 的 OpenSSH 客户端 |
| `externally-managed-environment` | 忘了激活 venv，先 `source ~/venvs/cnn/bin/activate` |
| `No module named torch` | 环境不对，找 Lucky，不要自己装 |
| `torch.cuda.is_available()` 是 False | 环境不对，找 Lucky |
| `No space left on device` | 磁盘满了，`df -h` 看，删自己的旧文件 |
| 训练断了 | `tmux attach -t 会话名` 回去看 |
| 其它 | 找秋爽，不自己重启 |

## 12. 每天怎么用（背这几句）

> 登录 → 看 GPU 和磁盘 → 激活环境 → tmux 里跑 → detach → 拉结果 → 关自己的会话。
>
> 不碰系统，不碰别人，密码不写进任何文件。
