## 一、资源概览

华硕提供基于 Ascent GX10 实机的云端节点，搭载 NVIDIA GB10 超级芯片，FP4 算力最高 1 PFlop，采用多级温控双风扇散热。节点预装 NVIDIA AI 开发环境，比赛期间提供 7×24 小时算力调用环境，硬件规格与预装软件栈与零售版一致。

节点清单列出 15 台设备。请使用组委会分配给本队的节点和连接信息，先完成 SSH 登录与环境自检，再通过 SSH 隧道访问服务。公网业务端口须经技术支持确认目标节点后使用。

| 业务登记 | 8888 | 8010 + i | 8011 |
| 业务登记 | 9000 | 9010 + i | 9011 |

例如，序号 15 的 gx10-3f7a 使用 SSH 端口 6025。其 7000、8888、9000 对应的公网登记端口依次为 7025、8025、9025。

## 二、5 分钟快速开始

以 gx10-3b9d 为例。将 6011 替换为本队 SSH 端口。第一步在本地终端执行；登录后第二、三步在节点执行；第四步使用本地浏览器。

### 1. 本地终端：登录并转发 8888 端口

```bash
ssh -p 6011 -L 8888:localhost:8888 asus_gx10@61.172.235.130
```

### 2. 节点终端：检查 GPU 状态

```bash
nvidia-smi
```

### 3. 节点终端：启动仅供隧道访问的测试服务

```bash
python3 -m http.server 8888 --bind 127.0.0.1
```

### 4. 本地浏览器：保持 SSH 窗口开启，访问下方地址

```text
http://localhost:8888
```

浏览器显示目录列表即表示本地到节点服务的访问链路可用。测试完成后，在运行测试服务的节点终端按 Ctrl+C 停止服务。测试服务不应改为无鉴权公网访问。

> **快速开始检查**
> SSH 使用分配的公网端口，不能直接填 22。SSH 隧道访问本地 localhost，节点测试服务监听 127.0.0.1；公网访问才需要监听 0.0.0.0。若命令提示端口已占用，请停止自己的测试服务或按第五章更换本地端口。

## 三、SSH 登录

### 3.1 命令行登录

在 Windows PowerShell 或 CMD、macOS 终端、Linux 终端执行下列命令。命令中的端口和账号必须与本队分配信息一致。

```bash
ssh -p 6011 asus_gx10@61.172.235.130
```

首次连接时，按终端提示确认主机指纹后输入 yes，再输入组委会发放的密码。输入密码时屏幕不显示字符，输完后按回车。登录成功后，后续开发命令在节点终端执行；文件传输和隧道命令在本地终端执行。

### 3.2 图形化客户端

若使用 MobaXterm、Xshell、FinalShell、PuTTY 等工具，按下表填写连接信息：

| 字段 | 填写内容 |
| --- | --- |
| Host / 主机 | 61.172.235.130 |
| Port / 端口 | 6011，替换为本队 SSH 端口 |
| User / 用户名 | asus_gx10 |
| Password / 密码 | 由组委会通过私密渠道单独发放 |
| 协议 | SSH |

> **开发环境与服务启动**
> 华硕节点预装 NVIDIA AI 开发环境。具体软件版本、可用工具和端口占用请按第七章检查；使用某个工具前先确认它可用，预装环境不代表 Web 服务已启动。

## 四、服务访问与公网端口

### 4.1 访问方式

开发调试使用 SSH 隧道，浏览器访问本地 localhost。清单登记了 7000、8888、9000 三类业务目标端口，公网示例为 7011、8011、9011；同一行业务内网地址与 SSH 地址不同，不能据此认定它们已经指向本队节点。

确认前：通过第二章或第五章的 SSH 隧道访问本队服务。

公网发布前：请技术支持确认目标节点及对应业务端口，再设置服务鉴权。

### 4.2 监听地址与启动示例

SSH 隧道方式可将节点服务绑定到 127.0.0.1。以下命令在已具备相应工具和项目文件时执行；任选一个服务，不要同时占用相同端口。Gradio 一行为 Python 代码，写入已有 demo 对象所在的应用文件。

**JupyterLab**

```bash
jupyter lab --ip 127.0.0.1 --port 8888 --no-browser
```

**Gradio：写入已有应用的 Python 代码**

```python
demo.launch(server_name="127.0.0.1", server_port=8888)
```

**FastAPI / Uvicorn：app.py 中已定义 app 对象**

```bash
uvicorn app:app --host 127.0.0.1 --port 9000
```

**vLLM：将 MODEL_PATH 替换为实际模型名称或路径**

```bash
vllm serve MODEL_PATH --host 127.0.0.1 --port 9000
```

**Ollama**

```bash
OLLAMA_HOST=127.0.0.1:9000 ollama serve
```

在节点执行下列命令，确认相应端口已监听。8888 和 9000 服务通过第五章的隧道访问。7000 端口如需使用，同样通过 SSH 隧道转发。

```bash
ss -tlnp | grep -E "7000|8888|9000"
```

**隧道方式：节点服务监听 127.0.0.1 即可**

### 4.3 安全提醒

> **公网访问前的要求**
> 只有在技术支持确认业务映射目标正确后，才按对应端口对外提供服务。公网方式需将服务监听地址改为 0.0.0.0，并先设置 token 或密码。未配置鉴权的服务继续通过 SSH 隧道访问。不要对外开放无鉴权的文件管理器、Web 终端或数据库控制台，用完及时关闭。

## 五、通过 SSH 隧道访问服务

在本地终端执行端口转发命令，登录到本队节点后保持连接。下例将节点上的 7860 端口转发到本地 7860；节点服务需先在对应端口启动。使用其他端口时，将本地端口和节点端口替换为实际值。

把节点上的 7860 端口映射到你本地的 7860：

```bash
ssh -p 6011 -L 7860:localhost:7860 asus_gx10@61.172.235.130
```

一条命令同时转发多个端口：

```bash
ssh -p 6011 -L 7860:localhost:7860 -L 6006:localhost:6006 asus_gx10@61.172.235.130
```

连接保持期间，在本地浏览器打开 http://localhost:7860 或 http://localhost:6006。此处 localhost 指本机；转发目标 localhost 指 SSH 登录的节点。节点服务监听 127.0.0.1 即可。SSH 断开后，需重新建立隧道才能访问。

若第四章示例服务使用 8888 或 9000，使用下面的转发命令，浏览器访问 http://localhost:8888 或 http://localhost:9000。

```bash
ssh -p 6011 -L 8888:localhost:8888 -L 9000:localhost:9000 asus_gx10@61.172.235.130
```

使用 VS Code Remote-SSH 时，可在“端口”面板转发所需端口。本地端口如已被占用，可换用其他本地端口；例如下面命令的 17860 是本地端口，7860 仍是节点服务端口。

```bash
ssh -p 6011 -L 17860:localhost:7860 asus_gx10@61.172.235.130
```

更换后在本地浏览器访问 http://localhost:17860。

## 六、文件传输

### 6.1 使用 scp 传输小文件

以下命令在本地终端执行。scp 的端口参数为大写 -P，ssh 为小写 -p。示例中的 train.py、project 和 result.json 须替换为实际存在的文件或目录；`~/` 表示节点登录用户的主目录。

本地 → 节点：

```bash
scp -P 6011 ./train.py asus_gx10@61.172.235.130:~/
```

本地目录 → 节点：

```bash
scp -P 6011 -r ./project asus_gx10@61.172.235.130:~/
```

节点 → 本地：

```bash
scp -P 6011 asus_gx10@61.172.235.130:~/result.json ./
```

### 6.2 使用 rsync 传输中等文件

100 MB～1 GB 的文件可使用 rsync 断点续传和增量同步；需本地与节点均具备 rsync。网络中断后可重跑同一条命令。下例在本地终端执行，将 `dataset/` 的内容同步到节点的 `~/dataset/`。

```bash
rsync -avzP -e "ssh -p 6011" ./dataset/ asus_gx10@61.172.235.130:~/dataset/
```

参数含义：`-a` 保留属性　`-v` 显示过程　`-z` 压缩传输　`-P` 断点续传 + 进度条

### 6.3 超过 1 GB 的文件在节点下载

> **超过 1 GB 的文件禁止使用 scp 上传**
> 上传模型和数据集优先在节点上直接下载，避免长时间占用共享公网带宽。仅存在于本地的数据，按下方方法压缩切片，再使用 rsync 分批传输，或联系技术支持处理。

先 SSH 登录节点，再按实际来源选择下载方式。将 MODEL_ID、MODEL_NAME、DOWNLOAD_URL 替换为实际值，并使用自己有权限写入的目录。下载前用 `df -h` 检查空间；示例的 `~/data/` 目录须先准备好。

节点：使用 ModelScope 下载模型

```bash
pip install modelscope
modelscope download --model MODEL_ID --local_dir ~/models/MODEL_NAME
```

通用直链下载，`-c` 支持断点续传：

```bash
wget -c DOWNLOAD_URL -O ~/data/dataset.tar.gz
```

如数据只能从本地传入，在具备 tar、split 的本地终端压缩并按 500 MB 切片，选择低峰时段用 rsync 分批传输。全部切片放在节点同一目录后，在该目录运行还原命令。无法使用这些工具时联系技术支持。

本地：压缩并切片

```bash
tar czf - ./data | split -b 500m - data.tar.gz.part_
```

节点：全部切片传完后，在其所在目录还原

```bash
cat data.tar.gz.part_* | tar xzf -
```

## 七、环境自检与长任务

登录后在节点执行下列命令，记录 GPU 状态、可用磁盘空间及软件版本。nvcc 和 Docker 的可用性以实际环境为准；命令不存在或无权限时联系技术支持，不要自行改动宿主机驱动或系统配置。

```bash
nvidia-smi             # GPU 状态与驱动信息
nvcc -V                # CUDA 编译器版本，如已安装
df -h                  # 磁盘剩余空间
free -h                # 内存
nproc                  # CPU 核数
python3 -V             # Python 版本
docker info            # Docker 可用性
```

### 7.1 使用 tmux 运行长任务

训练等长时间任务放在 tmux 会话中运行，避免 SSH 断开影响前台任务。先新建会话，在会话内运行自己的任务，再脱离会话。重新登录后可查看会话并恢复连接；如 tmux 不可用，联系技术支持。

```bash
tmux new -s train        # 新建会话
```

在会话内运行任务；按 `Ctrl+B` 松开，再按 `D` 脱离。

```bash
tmux ls                  # 查看已有会话
tmux attach -t train     # 恢复会话查看任务
```

## 八、注意事项与使用红线

节点由组委会统一提供，参赛者共享网络与运维环境。请遵守以下规则。违反红线条款的队伍将被回收节点、取消参赛资格，组委会保留追究相应法律责任的权利。

### 8.1 禁止事项

1. 严禁违法违规活动，包括加密货币挖矿、网络攻击、端口扫描、暴力破解、漏洞利用、搭建翻墙代理或跳板服务、制作传播木马病毒、存储分发违禁内容、爬取或倒卖受法律保护的数据。
2. 严禁扫描、探测、入侵其他节点或跳板机，严禁尝试登录未分配给本队的机器。
3. 严禁将节点用于与比赛无关的商业用途，严禁转租、转售、转借节点，严禁将账号密码分享给非本队成员或公开发布。
4. 严禁修改系统级配置，包括登录密码、SSH 服务配置、防火墙与 iptables 规则、网络路由、用户与权限体系。配置需求请联系技术支持。
5. 严禁卸载或降级 GPU 驱动、刷写固件、改动 BIOS。如需特定 CUDA 版本，使用 conda 环境或 Docker 容器隔离，不改动宿主机驱动。
6. 严禁执行 reboot、shutdown、poweroff 等重启或关机操作。异常情况请联系技术支持处理。

### 8.2 严格限制

7. 单次超过 1 GB 的文件禁止使用 scp 上传。请在节点内直接下载，或用 rsync 分批断点续传，避免长时间占用共享带宽。
8. 用 `df -h` 关注磁盘空间，保持至少 20% 空闲。及时清理自己的下载压缩包、废弃 checkpoint 和 pip、HuggingFace 缓存。
9. 公网服务必须设置 token 或密码。严禁公开无鉴权的文件管理器、Web 终端或数据库控制台。7000、8888、9000 相关公网业务映射使用前须确认目标节点。
10. 严禁存储个人隐私数据、公司内部数据、涉密信息或未获授权的第三方数据集。SSH 隧道不改变这一要求。
11. 长时间任务使用 tmux 或 screen 托管，不在 SSH 前台直接运行训练。

### 8.3 数据安全与备份

12. 节点不提供数据备份或快照。硬件故障、误删、磁盘写满均可能导致数据丢失，请自行备份。
13. 及时将代码 push 到自己的 Git 仓库；定期将模型权重和实验结果下载到本地，或上传到自己的对象存储。
14. 比赛结束后组委会统一回收节点并清空磁盘，数据不可恢复。请在组委会通知的截止时间前完成备份和迁移。

### 8.4 使用礼仪

15. 只使用本队获分配的节点。若发现可登录其他机器，立即上报组委会并停止访问。
16. 提前完成比赛或不再使用节点时，通知组委会释放资源。
17. 设备故障、GPU 异常、无法登录时，及时联系技术支持，不自行重启或重装系统。

> **结束使用前关闭**
> 不再需要的公网服务，保存代码和实验结果，按组委会通知完成备份与迁移。结束使用节点请通知组委会；不要执行关机或重启。
